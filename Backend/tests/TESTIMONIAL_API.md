# Testimonial redesign contract

- `GET /api/student/testimonial?type=text|video`: `{data: object|null}`. Omitted type selects text. Owner only; active student required.
- `PUT /api/student/testimonial`: omitted `type` selects text. Text: `context` required string max255, `quote` required min20/max500, `consent_public` accepted. Video: `context` required max255, `title` required max255, optional nullable `quote` max500, `video_url` and `video_thumbnail` required max2048, `consent_public` accepted. `video_title` aliases `title`; conflicting aliases rejected. All other fields prohibited.
- Video student links: HTTPS YouTube (11-character ID), Instagram post/reel/tv, Google Drive file/open (10–200-character ID). No native remote MP4 submission, credentials, custom port, or arbitrary fetch. Thumbnail: HTTPS JPG/JPEG/PNG/WebP URL; validation checks URL syntax/extension, not remote content. No fetch/upload required. Managed MP4/WebM remain supported by Admin/media resolver. Remote native Admin videos require HTTPS; HTTP allowed only for exact loopback hosts (`localhost`, `127.0.0.1`, `::1`). Admin thumbnails accept managed image references or strict HTTPS image URLs; no HTTP thumbnail exception. General image/audio rules unchanged.
- Student response retains existing fields and adds `type`, `title`, `video_title`, `video_url`, `video_thumbnail`, `image` (account avatar), `landing`, `show_on_testimonials`, and media `_resolved_url` fields. Avatar and video thumbnail are separate. Text quote remains unchanged. Video quote is description.
- Pending/rejected submissions may be replaced per type. Approved submission returns 409. Duplicate submission uses same ID. `(user_id,type)` DB unique plus owner row lock and shared media lock serialize saves.
- Admin student PATCH allows only `moderation_status`, `moderation_note`, `published`, `landing`, `show_on_testimonials`, `sort_order`. Identity/content/type/consent cannot be edited. First-ever approved transition requires consent and activates all three publication/channel flags. Repeated approval, including rejected-to-approved after previous approval, never reactivates disabled flags. `first_approved_at` persists through rejection/resubmission.
- `published=false` suppresses every public channel without changing channel choices. Non-approved or non-consenting content never public.
- `GET /api/testimonials` requires `show_on_testimonials=true`. `?landing=true` independently requires `landing=true`. Legacy `?landing=false` requires testimonials channel and excludes landing entries. Common gates: published, approved, consent. Public payload includes content/type/channel flags, excludes owner ID/consent/moderation fields. Student name/avatar resolve from current account.
- Migration forward-only. Existing video+quote rows become `type=video`; quote retained as video description, not duplicated into text card. Old non-video rows become text. Old `published` initializes testimonials-channel visibility. Old approved rows get approval history, preventing reactivation. Legacy videos may keep null thumbnail; channel-only updates and deletion remain valid. New/changed Admin videos require thumbnail; legacy managed media retained.
- `User::testimonials()` is hasMany. Compatibility `User::testimonial()` selects text only.
- Demo command preserves schema/storage guard and idempotency; new demo videos upload existing brand `assets/video.png` as managed thumbnail. Existing demo rows untouched.

Tests: `TestimonialRedesignTest`, `TestimonialRaceTest`, updated `PublicContentTest` and `TestimonialDemoTest`; use guarded runner in `tests/README.md`. No ordinary development or production migrations performed.
